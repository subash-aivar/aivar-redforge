# M25D Implementation Specification — Part 1
## Enterprise Credential Vault: Background Workers & Operational Automation
### Version 1.0 FROZEN | Authority: M25 Architecture v1.0 FINAL + M25C Spec v1.0

---

## §1. Goals

M25D delivers the background operational machinery that makes the credential vault self-managing:

1. **Rotation Scheduler** — polls for credentials with active `RotationPolicy` where rotation is due; triggers `rotate_credential` via the application service.
2. **Expiration Scanner** — polls for credentials with active `ExpirationPolicy` or explicit `expires_at` where the active version is past expiry; triggers `expire_credential`.
3. **Version Pruner** — for each credential with a `RotationPolicy.max_versions_kept` constraint, deletes SUPERSEDED versions that exceed the cap. Domain-level cleanup; does not modify aggregate state.
4. **DEK Rewrap Worker** — when a master KMS key is rotated, rewraps all key envelopes for active and pending versions to the new master key ID. Idempotent. Rate-limited.
5. **Rotation Warning Notifier** — emits domain events for credentials approaching their rotation deadline. Does not trigger rotation; observation only.
6. **Worker Host** — asyncio-based worker host that starts, stops, and health-checks all four workers as a unit.
7. **Worker metrics and observability** — per-worker Prometheus gauges and counters; structured logging of every cycle.
8. **Integration tests** — PostgreSQL-backed integration tests verifying each worker's behavior against real credential data.

## §3. Architecture Constraints

**Workers use application services, not domain objects directly.** The `RotationSchedulerWorker` calls `CredentialApplicationService.rotate_credential()`. It does not construct domain aggregates. The full application service lifecycle (UoW, audit, events) executes on every triggered rotation.

**Workers never share a UoW across poll cycles.** Each triggered operation opens and closes its own UoW via the factory. The worker is stateless across cycles.

**No blocking I/O on the event loop.** All PostgreSQL queries in workers are async. All KMS calls are async. No `time.sleep()` — use `asyncio.sleep()`.

**Workers run in the same process as the FastAPI app**, started during application lifespan. This is the existing pattern: `ContinuousValidationSchedulerWorker` and `DLQReplayWorker` both follow this model (see `backend/src/redforge/application/continuous_validation/scheduler_worker.py`).

**SKIP LOCKED for claim-style polling.** The rotation and expiration scanners use `SELECT FOR UPDATE SKIP LOCKED` to claim a batch of due credentials. This prevents duplicate processing when multiple worker processes run (replicas). A `claimed_at` column on the schedule state table tracks in-flight items and expires stale claims.

**Domain services are injected into workers.** `RotationPlannerService` and `PolicyEvaluatorService` are used by workers to evaluate due status before querying the database, and to perform pre-flight checks. They are stateless pure services.

**`rotate_credential` for scheduled rotation uses `trigger="SCHEDULED"`** and no `new_plaintext_secret` — the domain application service or a separate `schedule_rotation` command handles generating the new secret. See §5.1.

Actually: the `RotateCredentialCommand` requires `new_plaintext_secret: bytes`. For **scheduled rotation**, the worker must supply the new secret. The secret is a zero-knowledge operation — the new secret is generated by the **encryption adapter** (generate random bytes of the same size as the original payload_size). The worker calls `IEncryptionPort`-adjacent logic: generate a new random secret of the policy-specified length, or use `os.urandom(policy.rotation_secret_length or 32)` as a default. This is an operational secret generation, not a domain concern. The worker generates the new plaintext, calls `rotate_credential`, and then calls `commit_rotation` after a configurable commit window (or immediately if `policy.auto_commit` is True — see §5.1 for the policy field addition).

## §5. Worker Specifications

### 5.1 `RotationSchedulerWorker`

#### Purpose
Periodically queries for credentials where rotation is due per their `RotationPolicy`. Triggers `rotate_credential` followed by `commit_rotation` (when `auto_commit` is true) for each due credential.

#### New policy field required

Add `auto_commit: bool = True` to `RotationPolicy`. This is an additive field:
- `auto_commit=True` — the worker calls both `rotate_credential` and `commit_rotation` in sequence. Appropriate for simple automated rotation where no external validation is needed.
- `auto_commit=False` — the worker calls only `rotate_credential` (begins rotation). A human or external process must call `commit_rotation` within `policy.commit_window_hours` hours, or the scheduler calls `abort_rotation` after the window expires.

This requires:
1. Adding `auto_commit: bool` and `commit_window_hours: int = 24` to `RotationPolicy` aggregate (`__slots__` and `__init__`).
2. Adding the corresponding column to `credential_vault_rotation_policies` ORM model and migration.
3. Updating `RotationPolicyDTO` to include the new fields.
4. Updating the `CreateRotationPolicyCommand` and `UpdateRotationPolicyCommand`.

All of these are additive changes. The domain enforces no new invariants.

#### Poll algorithm

```
For each cycle:
  1. CLAIM batch: SELECT top N credentials due for rotation via SKIP LOCKED
  2. For each claimed credential:
     a. Load credential + active version + rotation policy
     b. Verify due: RotationPlannerService.is_rotation_due(credential, policy, version.created_at, now)
     c. If due:
        - Generate new_plaintext_secret (os.urandom(payload_size or 32))
        - Call await credential_svc.rotate_credential(RotateCredentialCommand(..., trigger="SCHEDULED", ...))
        - If auto_commit: Call await credential_svc.commit_rotation(CommitRotationCommand(...))
     d. Update schedule_state: last_rotated_at = now, next_due_at = next_rotation_at(...)
     e. RELEASE claim
  3. Sleep poll_interval_s
```

#### Schedule state table

`credential_vault_rotation_schedule_state`:

| Column | Type | Notes |
|---|---|---|
| `credential_id` | `UUID PK` | FK to credentials |
| `tenant_id` | `UUID NOT NULL` | |
| `last_checked_at` | `TIMESTAMPTZ NOT NULL` | |
| `last_rotated_at` | `TIMESTAMPTZ NULLABLE` | |
| `next_due_at` | `TIMESTAMPTZ NOT NULL` | precomputed for fast poll |
| `claimed_at` | `TIMESTAMPTZ NULLABLE` | set when in-flight |
| `claim_expires_at` | `TIMESTAMPTZ NULLABLE` | stale claim expiry |

**Poll query (SKIP LOCKED):**
```sql
SELECT credential_id, tenant_id
FROM credential_vault_rotation_schedule_state
WHERE next_due_at <= NOW()
  AND (claimed_at IS NULL OR claim_expires_at < NOW())
ORDER BY next_due_at ASC
LIMIT :batch_size
FOR UPDATE SKIP LOCKED
```

After claiming: `UPDATE ... SET claimed_at = NOW(), claim_expires_at = NOW() + '10 minutes'`.
After processing: `UPDATE ... SET last_rotated_at = NOW(), next_due_at = :next, claimed_at = NULL, claim_expires_at = NULL`.

#### Constructor

```python
class RotationSchedulerWorker:
    def __init__(
        self,
        credential_service: CredentialApplicationService,
        schedule_repo: RotationScheduleRepository,
        rotation_planner: RotationPlannerService,
        credential_repo: ICredentialRepository,   # for pre-flight check
        version_repo: ICredentialVersionRepository,
        policy_repo: IRotationPolicyRepository,
        system_principal_id: uuid.UUID,            # service-account UUID from config
        worker_id: str = "rotation-scheduler-1",
        poll_interval_s: float = 60.0,
        batch_size: int = 10,
        max_concurrent: int = 3,
    ) -> None: ...
```

#### Lifecycle (standard pattern)

```python
async def start(self) -> None:
    self._running = True
    self._task = asyncio.create_task(self._poll_loop(), name="rotation-scheduler")

async def stop(self) -> None:
    self._running = False
    if self._task:
        self._task.cancel()
        with contextlib.suppress(asyncio.CancelledError):
            await self._task

@property
def is_running(self) -> bool:
    return self._running and self._task is not None and not self._task.done()
```

#### `_poll_loop`

```python
async def _poll_loop(self) -> None:
    while self._running:
        try:
            await self._run_cycle()
        except Exception as exc:
            logger.warning("rotation_scheduler_cycle_failed", error=str(exc))
        await asyncio.sleep(self._poll_interval_s)
```

#### `_run_cycle`

```python
async def _run_cycle(self) -> None:
    claimed = await self._schedule_repo.claim_batch(self._batch_size)
    if not claimed:
        return
    semaphore = asyncio.Semaphore(self._max_concurrent)
    async def _process_one(item: ScheduleItem) -> None:
        async with semaphore:
            try:
                await self._process_credential(item)
            except Exception as exc:
                logger.warning("rotation_failed", credential_id=str(item.credential_id), error=str(exc))
                await self._schedule_repo.release_claim(item.credential_id, item.tenant_id)
    await asyncio.gather(*[_process_one(item) for item in claimed])
```

### 5.2 `ExpirationScannerWorker`

#### Purpose
Scans credentials whose active version is past expiry (per `ExpirationPolicy` or explicit `expires_at`). Calls `credential_svc.expire_credential()` for each expired credential.

#### Poll algorithm

```
For each cycle:
  1. CLAIM batch: SELECT credentials where active version expires_at <= NOW()
     OR (policy.hard_expire AND version.created_at + ttl_days <= NOW())
  2. For each claimed:
     a. Load credential + active version + expiration policy (if any)
     b. Verify: PolicyEvaluatorService.is_version_expired(version, policy, now)
     c. If expired: call await credential_svc.expire_credential(cmd)
     d. Update expiration_schedule_state
  3. Sleep poll_interval_s (default: 300s)
```

#### Schedule state table

`credential_vault_expiration_schedule_state`:

| Column | Type |
|---|---|
| `credential_id` | `UUID PK` |
| `tenant_id` | `UUID NOT NULL` |
| `last_scanned_at` | `TIMESTAMPTZ NOT NULL` |
| `expires_at` | `TIMESTAMPTZ NULLABLE` (from version.expires_at) |
| `policy_expiry_at` | `TIMESTAMPTZ NULLABLE` (computed from policy) |
| `next_scan_at` | `TIMESTAMPTZ NOT NULL` |
| `claimed_at` | `TIMESTAMPTZ NULLABLE` |
| `claim_expires_at` | `TIMESTAMPTZ NULLABLE` |

**Warning emission**: Before expiry, when `PolicyEvaluatorService.should_warn_expiration(...)` returns True, the worker emits a `CredentialExpirationWarning` domain event via the `IEventPublisher`. This is a new domain event (additive to M25A events):

### 5.3 `VersionPrunerWorker`

#### Purpose
For each credential with `RotationPolicy.max_versions_kept < actual_superseded_count`, deletes the oldest SUPERSEDED versions until the count equals `max_versions_kept`. This is a physical data cleanup operation — it deletes rows from `credential_vault_versions`.

**Domain preconditions (enforced before deletion):**
- Only `SUPERSEDED` versions may be deleted. Never `ACTIVE`, `PENDING`, or `REVOKED`.
- Cannot delete if the version is referenced by an audit entry as the "previous active version" — check for referential audit entries (optional in M25D; can skip if FK constraint not in place).
- Deletion is performed directly via repository, not via domain aggregate method (no domain method exists for version pruning).

#### Algorithm

```
For each cycle:
  1. Query credentials where superseded_count > max_versions_kept
  2. For each:
     a. Load SUPERSEDED versions ordered by version_number ASC
     b. Delete oldest (count - max_versions_kept) versions
     c. Log pruned_count with credential_id, tenant_id
  3. Sleep poll_interval_s (default: 3600s = 1 hour)
```

#### `VersionPrunerRepository` (new, not in domain ABC)

Adds a new infrastructure-only repository for the pruner:
```python
class VersionPrunerRepository:
    async def find_credentials_exceeding_max_versions(
        self, batch_size: int
    ) -> list[PruneCandidate]:
        """
        Returns credentials where SUPERSEDED version count > rotation_policy.max_versions_kept.
        Uses a join between credentials, rotation_policies, and a subquery counting versions.
        """

    async def delete_superseded_versions(
        self,
        credential_id: CredentialId,
        version_ids_to_delete: list[VersionId],
        tenant_id: TenantId,
    ) -> int:
        """
        Deletes the specified SUPERSEDED versions. Returns count deleted.
        Raises if any version_id is not in SUPERSEDED state (safety guard).
        """
```

The `delete_superseded_versions` query:
```sql
DELETE FROM credential_vault_versions
WHERE id = ANY(:ids) AND tenant_id = :tid AND version_state = 'SUPERSEDED'
RETURNING id
```
If `len(returning) != len(ids)` → some versions were not SUPERSEDED; log warning, do not fail.

#### Constructor

```python
class VersionPrunerWorker:
    def __init__(
        self,
        pruner_repo: VersionPrunerRepository,
        version_repo: ICredentialVersionRepository,  # for loading version list
        session_factory: async_sessionmaker[AsyncSession],
        worker_id: str = "version-pruner-1",

    ) -> None: ...
```

The pruner opens its own session (not via `IUnitOfWork`) because it does not use the application service and has no audit trail. The deletion IS logged via `structlog`.

### 5.4 `DekRewrapWorker`

#### Purpose
Rewraps all `KeyEnvelope` records from an old master key to a new master key. Used when the KMS master key is rotated. This is a long-running, rate-limited, idempotent background job.

**Trigger**: Not automatic. Started by operator action (API endpoint or config flag `CREDENTIAL_VAULT_REWRAP_MASTER_KEY_ID=<new_key_id>`).

**Idempotency**: Tracks progress per version in `credential_vault_dek_rewrap_progress` table. A version with `rewrapped_at IS NOT NULL` is skipped.

#### Algorithm

```
1. Read target_master_key_id from config/env
2. Query all versions WHERE master_key_id != target AND rewrapped_at IS NULL
   ORDER BY created_at ASC LIMIT batch_size
3. For each version:
   a. Load version (verify tenant)
   b. old_envelope = version.key_envelope
   c. new_envelope = await kms_adapter.rewrap_dek(old_envelope, target_master_key_id)
   d. UPDATE credential_vault_versions SET wrapped_dek = :new, master_key_id = :new_kid,
      wrapping_algorithm = :algo, key_created_at = NOW() WHERE id = :vid
   e. INSERT/UPDATE credential_vault_dek_rewrap_progress SET rewrapped_at = NOW()
4. Sleep rate_limit_delay_ms between each version (default: 50ms)
5. Exit when no more versions need rewrap
```

**`credential_vault_dek_rewrap_progress`** table (migration `0045`):

| Column | Type |
|---|---|
| `id` | `UUID PK` |
| `version_id` | `UUID NOT NULL, UNIQUE` |
| `tenant_id` | `UUID NOT NULL` |
| `old_master_key_id` | `VARCHAR(256) NOT NULL` |
| `new_master_key_id` | `VARCHAR(256) NOT NULL` |
| `started_at` | `TIMESTAMPTZ NOT NULL` |
| `rewrapped_at` | `TIMESTAMPTZ NULLABLE` |
| `error` | `TEXT NULLABLE` |

The rewrap worker reads the old DEK, rewraps to the new master key, and writes the new envelope atomically. The version's `row_version` is incremented via the same optimistic lock pattern.

#### Constructor

```python

        self,
        kms_adapter: IKeyManagementPort,
        rewrap_repo: DekRewrapProgressRepository,

        target_master_key_id: str,
        worker_id: str = "dek-rewrap-1",

        rate_limit_delay_ms: int = 50,
```

### 5.5 `CredentialVaultWorkerHost`

#### Purpose
Composes and lifecycle-manages all four workers. Registered with FastAPI `@app.on_event("startup")` and `@app.on_event("shutdown")` (or lifespan context manager pattern).

```python
class CredentialVaultWorkerHost:
    def __init__(
        self,
        rotation_worker: RotationSchedulerWorker,
        expiration_worker: ExpirationScannerWorker,
        pruner_worker: VersionPrunerWorker,
        rewrap_worker: DekRewrapWorker | None,  # None if rewrap not configured
    ) -> None:
        self._workers = [w for w in [rotation_worker, expiration_worker, pruner_worker, rewrap_worker] if w is not None]

    async def start(self) -> None:
        for worker in self._workers:
            await worker.start()

    async def stop(self) -> None:
        for worker in reversed(self._workers):
            await worker.stop()

    @property
    def is_healthy(self) -> bool:
        return all(w.is_running for w in self._workers)

    def stats(self) -> dict[str, object]:
        return {w.worker_id: {"running": w.is_running, **w.stats()} for w in self._workers}
```

`DekRewrapWorker` is `None` when `CREDENTIAL_VAULT_REWRAP_MASTER_KEY_ID` is not set.

## §6. Schedule State Population

When a credential is created with a `RotationPolicy`, the `RotationSchedulerWorker` needs an entry in `credential_vault_rotation_schedule_state`. This is done by the application service after commit — or by the scheduler's initialization scan.

**Approach:** On startup, the `RotationSchedulerWorker` runs a reconciliation query:
```sql
INSERT INTO credential_vault_rotation_schedule_state (credential_id, tenant_id, last_checked_at, next_due_at)
SELECT c.id, c.tenant_id, NOW(),
       v.created_at + (p.interval_days * INTERVAL '1 day')
FROM credential_vault_credentials c
JOIN credential_vault_versions v ON v.id = c.active_version_id
JOIN credential_vault_rotation_policies p ON p.id = c.rotation_policy_id
WHERE c.rotation_policy_id IS NOT NULL
  AND c.state = 'ACTIVE'
  AND p.auto_rotate = TRUE
  AND c.id NOT IN (SELECT credential_id FROM credential_vault_rotation_schedule_state)
ON CONFLICT (credential_id) DO NOTHING
```

This reconciliation runs once at worker startup (not every cycle).

Similarly for `ExpirationScannerWorker` with the expiration schedule state.

## §9. Security Model

### Rotation secret generation

The `RotationSchedulerWorker` generates new plaintext secrets using `os.urandom(32)` by default, or `os.urandom(policy.secret_length_bytes)` if the policy specifies a length. The secret is passed directly to `RotateCredentialCommand.new_plaintext_secret`. It is never logged. It is zeroed by the application service's `AesGcmEncryptionAdapter`.

The rotating system principal is `system_principal_id` — a service account UUID configured in the environment (`CREDENTIAL_VAULT_SYSTEM_PRINCIPAL_ID`). This principal must have `PERMISSION_ROTATE` on all credentials targeted for scheduled rotation. This is enforced by the permission adapter.

### DEK rewrap authorization

The `DekRewrapWorker` requires `CREDENTIAL_VAULT_REWRAP_AUTHORIZED=true` environment variable AND `CREDENTIAL_VAULT_REWRAP_MASTER_KEY_ID` to be set. Both must be present to activate the worker. Activation without both is a startup error (logged and blocked).

### Claim expiry prevents deadlocks

If a worker crashes mid-processing, the `claim_expires_at` ensures the credential becomes claimable again after the window (default 10 minutes for rotation, 5 minutes for expiration). The next worker cycle will re-claim and re-process.

## §11. Concurrency and Idempotency

### SKIP LOCKED concurrency

When multiple FastAPI replicas run (e.g., 3 pods in Kubernetes), each has its own `CredentialVaultWorkerHost`. The `SELECT FOR UPDATE SKIP LOCKED` ensures only one pod claims each credential per cycle. The `claim_expires_at` ensures recovery from crashes.

### Idempotency

**Rotation**: If `rotate_credential` is called on a credential already in `ROTATING` state, the domain raises `ConcurrentRotationConflict`. The scheduler catches this, releases the claim, and logs a warning. It does not retry the same cycle.

**Expiration**: If `expire_credential` is called on an already-EXPIRED credential, the domain raises `InvalidStateTransition`. The scanner releases the claim and moves `next_scan_at` forward.

**Version pruner**: `DELETE ... WHERE version_state = 'SUPERSEDED'` is naturally idempotent — deleted versions cannot be re-deleted.

**DEK rewrap**: The `credential_vault_dek_rewrap_progress` table tracks completion. `rewrapped_at IS NOT NULL` rows are skipped. Idempotent by design.

## §12. Configuration

All worker configuration is via environment variables:

| Variable | Default | Description |
|---|---|---|
| `CREDENTIAL_VAULT_ROTATION_POLL_S` | `60` | Rotation scheduler poll interval |
| `CREDENTIAL_VAULT_ROTATION_BATCH_SIZE` | `10` | Max credentials per rotation cycle |
| `CREDENTIAL_VAULT_ROTATION_MAX_CONCURRENT` | `3` | Concurrent rotation tasks per cycle |
| `CREDENTIAL_VAULT_EXPIRATION_POLL_S` | `300` | Expiration scanner poll interval |
| `CREDENTIAL_VAULT_EXPIRATION_BATCH_SIZE` | `20` | Max credentials per expiration cycle |
| `CREDENTIAL_VAULT_PRUNER_POLL_S` | `3600` | Version pruner interval |
| `CREDENTIAL_VAULT_PRUNER_BATCH_SIZE` | `50` | Max credentials per pruner cycle |
| `CREDENTIAL_VAULT_SYSTEM_PRINCIPAL_ID` | required | Service account UUID for automated operations |
| `CREDENTIAL_VAULT_REWRAP_MASTER_KEY_ID` | unset | Target master key ID; activates DEK rewrap |
| `CREDENTIAL_VAULT_REWRAP_AUTHORIZED` | `false` | Must be `true` to activate DEK rewrap |
| `CREDENTIAL_VAULT_REWRAP_RATE_LIMIT_MS` | `50` | Delay between rewrap operations |
| `CREDENTIAL_VAULT_WORKERS_ENABLED` | `true` | Master switch for all workers |
